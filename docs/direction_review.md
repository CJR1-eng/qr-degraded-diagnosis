# 退化二维码白盒几何诊断项目 —— 完整实验总结与终止评估

> 用途：供第三方独立判断"是否应终止该方向"。
> 说明：以下所有数据均来自真实实验记录（合成数据集 + 三种解码器实测），未作任何修饰。结论部分为项目执行者的判断，欢迎挑战。

---

## 一、研究问题与原始假设

**目标**：面向 SCI Q3/Q4，研究退化二维码（透视畸变 + 失焦/运动模糊）的解码鲁棒性，定位为"成本敏感诊断-路由的延迟-解码率权衡"。

**原始假设**：主流解码器 ZXing 的对齐图案（Alignment Pattern）定位在退化条件下会误锁或漏检，导致解码失败。若能对对齐图案定位进行**白盒、零训练、可解释**的几何诊断与自适应修复，就能在不引入重依赖（保持 ZXing 轻量）的前提下，提升退化场景的解码鲁棒性。

**数据集**（均带真值）：
- E2 近轴模糊集：1000 张，高斯模糊 σ ∈ {0, 1.5, 1.75, 2.0, 2.25, 2.5, 2.75, 3.0, 3.5, 4.0} 共 10 档，每档 100 张。
- E4 透视退化集：600 张，6 条件（C0 清晰 / P1 轻透视 / P2 中透视 / P3 强透视 / P4 中透视+σ2 模糊 / P5 中透视+σ3 模糊），各 100 张，真值由生成过程的 Homography 提供。

## 二、完整实验脉络与结果

### 2.1 失效机理诊断

核心发现：ZXing 的仿射先验残差 P0（检测对齐图案与三点仿射外推位置的距离）在透视下**混淆两类性质迥异的误差**：

```
P0 ≈ ε_struct + ε_true
ε_struct（仿射先验的结构误差）≈ 1.86 ~ 3.77 模块
ε_true（真定位误差）≈ 0.03 ~ 0.09 模块（纯透视）
```

因此，基于 P0 的仿射门控在透视下会**大规模误拒**本已准确定位的对齐图案。

| 方法 | E2 (1000 张) | E4 (600 张) |
|---|---|---|
| ZXing ORIGINAL | 692 | 346 |
| 仿射 P0 门控 (τ=2) | 900 | **161（反恶化）** |
| 强制三点 | 900 | 100 |

### 2.2 提出的方法（E5）

1. **投影先验 p_proj**：用 3 个 Finder 中心 + 局部方向模块尺寸，闭式重建右下对齐图案中心（模块坐标 D−6.5），无角点提取、无 SVD。合成透视集上误差 0.0 模块（仿射先验中位误差 2.88 模块）。
2. **P0_proj 门控**：以 p_proj 替代仿射先验，识别误锁。
3. **投影回退**：对齐图案缺失时以 p_proj 作第四点，替代失效的仿射三点外推。
4. **校验触发微扰重试**：仅解码校验失败时，对第四点做亚模块微扰（成功样本零开销）。

| 方法 | E2 (1000) | E4 (600) |
|---|---|---|
| E5（无微扰） | 900 | 462 |
| **E5 + 微扰** | **900** | **490** |

E4 达到 490/600 = 81.67%，**与注入真值对齐中心的 Oracle 上界（490）完全持平**；E2 零回退。E4 相对 ORIGINAL：improved = 144，worsened = 0。

### 2.3 消融与延迟

**消融（E4，移除后损失）**：投影回退 94 张 > P0_proj 门控 37 张 > 微扰重试 28 张 > 搜索引导 0 张。

**延迟-收益**：净延迟 +1.4%，换取相对解码率 +41.6%；投影先验中位耗时 ~0.006 ms（微秒级），微扰仅失败样本 ~0.7 ms / 次。

## 三、决定性转折：跨解码器对照

这是终止判断的核心证据。用三个独立实现的解码器对同一 E4 数据集实测：

| 解码器 | E4 正确率 | 性质 |
|---|---|---|
| ZXing **Java 3.5.4** | 346 / 600 = 57.67% | 被改进对象 |
| E5 + 微扰（本文方法） | 490 / 600 = 81.67% | 在 ZXing Java 框架内改进 |
| OpenCV 5.0 | 529 / 600 = 88.17% | 独立实现 |
| **zxing-cpp 3.1.1** | **599 / 600 = 99.83%** | ZXing 的 C++ 重写版 |

**zxing-cpp 为何这么强（源码查证 `QRDetector.cpp`）**：它不用 Java ZXing 的"平行四边形外推"估右下角，而是用 `TraceLine` 追踪右上/左下 Finder 的**内边缘线求真实交点**（透视感知的右下角外推），叠加亚像素 Finder 精化（`CenterOfRing`）与多二值化 fallback。本文方法的唯一亮点（P5 上反超 OpenCV 69 vs 46），也被 zxing-cpp 的 99 压掉。

---

## 四、为什么建议终止（证据链）

1. **解码率被双重覆盖**：zxing-cpp（99.83%）和 OpenCV（88.17%）均高于本文方法（81.67%），且都是独立/重写实现。
2. **核心创新被覆盖**：本文的"投影先验 p_proj"与 zxing-cpp 的"TraceLine 边缘线交点"是**解决同一问题（透视感知的右下角外推）的两种方案**，后者已实现且更强。
3. **解决的并非普遍难点**：本文针对的"对齐图案失效"是 Java ZXing「单一全局透视 + 仿射先验」的**特定架构弱点**，而非退化 QR 解码的普遍难点——同源重写的 zxing-cpp 与独立实现的 OpenCV 都基本不受影响。这直接坐实了立项时预警的"防 ZXing bug 修复攻击"。
4. **唯一差异化缺少独立价值**：本文相对 zxing-cpp/OpenCV 的唯一差异化是"白盒可解释诊断"，但诊断的价值本应体现在"诊断→路由决策"带来的收益上；既然 zxing-cpp 已直接解出 99.83%，诊断的决策价值就被架空了。

---

## 五、残余价值（诚实呈现，供权衡）

1. **严谨的失效分析方法论**：Oracle 上界、P0 误差分解、逐组件消融、延迟-收益量化、跨解码器证伪——这套方法可复用于其他方向。
2. **对社区的负面结论**：坐实"Java ZXing 3.5.4 在透视下对齐图案失效、zxing-cpp/OpenCV 可规避"，对大量 Java/Android 开发者有实用参考价值。
3. **白盒诊断方法本身**：投影先验闭式解、误锁门控、微扰重试具备可解释性，理论上有意义，但缺应用场景支撑。

## 七、结论

本文方法在 ZXing 框架内严谨地达到了 Oracle 上界，实验方法论扎实；但跨解码器对照表明：**所解决的问题是 Java ZXing 的特定架构弱点，已被 zxing-cpp 用更彻底的方案（TraceLine 透视外推）解决，解码率被双重覆盖，核心创新难以成立。** 建议终止"改进 Java ZXing"方向，将"白盒诊断 + 失效分析"沉淀为开源项目，并将精力切回果实检测主线。
